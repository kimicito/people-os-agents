# Модель компетенций

Таблица, где для каждой роли и уровня описано, **что человек делает** — наблюдаемым поведением, а не качествами. «Ответственный» проверить нельзя; «доводит сделку до подписания без напоминаний руководителя» — можно.

## Из чего состоит (пример: менеджер по продажам)

| Элемент | Пример |
|---|---|
| Область | Квалификация сделок |
| Уровень «начальный» | Задаёт вопросы по чек-листу, приносит ответы руководителю |
| Уровень «самостоятельный» | Сам закрывает сделки без перспективы, объясняет почему |
| Уровень «ведущий» | Ставит критерии для команды, разбирает чужие сделки |
| Признак несоответствия | Держит в работе сделки без принимающего решение |

## Для чего используется

- **Найм** — вопросы на собеседовании выводятся из уровня.
- **Оценка** — разговор о результатах перестаёт быть обменом впечатлениями.
- **Рост** — ответ на «что мне сделать для следующего уровня» становится конкретным.
- **Грейды и вилки** — уровень компетенций связывается с уровнем оплаты.

## Правила описания

1. Уровень описывается через то, что человек **делает**, а не что знает или каким является. «Понимает методологию продаж» — непроверяемо; «заполняет квалификацию так, что руководитель не задаёт уточняющих вопросов» — проверяемо.
2. **Тест двух руководителей:** могут ли двое, глядя на работу человека, независимо поставить одинаковую оценку? Если нет, формулировка описывает впечатление.
3. Уровней не больше четырёх-пяти.
4. Индикатор проходит три вопроса: можно ли увидеть? можно ли подтвердить фактом? отличается ли от соседнего уровня?

## Где ломается

- Формулировки одинаково подходят бухгалтеру и продавцу — значит, ничего не различают.
- Оценивают раз в год ради формы, никто не читает.
- Компетенции подгоняют под конкретных людей.
- **Проверка на полезность:** оцените двух сотрудников с разным результатом. Если оценки совпали, модель не различает то, что различает бизнес.
